§1 · The idea

Rules learned from data

Normal programming: a person writes the rules, the computer applies them. Machine learning (ML) flips it: you give the computer examples and the right answers, and it works out the rules itself.

Programmingrules + data
→ answers
"if sleeves are long and…"
Machine learningdata + answers
→ rules
60,000 labelled photos
Model: the rule the computer learns, a formula with adjustable numbers. Parameters (or weights): those adjustable numbers. Training: adjusting them until the model's answers match the examples.
Where everything sits · tap a ring

The whole page is one idea that keeps growing: a formula with weights, a number that says how wrong it is, and a way to nudge the weights. Each section adds one small piece, ending at the CNN you built.

§2 · Linear regression

The simplest model: a line

Here are 24 measurements. A straight line ŷ = wx + b could summarise them. It has two weights: the slope w and the intercept b. The hat on ŷ means "the model's guess".

Loss: one number that says how wrong the model is. Here it's the mean squared error (MSE): for each point, take the vertical miss (ŷ − y), square it, then average. The orange squares are those squared misses, and MSE is their average area.

Gradient: the slope of the loss for each weight. ∂L/∂w answers "if w goes up a little, does the loss go up or down, and how fast?" Gradient descent: repeatedly step each weight a little against its gradient: w ← w − lr · ∂L/∂w. The learning rate (lr) sets the step size. The thing that applies this update is called the optimizer.

§3 · Logistic regression

Splitting two classes with a line

Now the answers aren't numbers but classes: each point is blue or red. We want a probability that a point is blue.

Step 1, a weighted sum, same as before: z = w₁x₁ + w₂x₂ + b. z can be any number.
Step 2, the sigmoid σ(z) = 1 / (1 + e−z) squashes z into a probability between 0 and 1. Big positive z → near 1 (blue), big negative → near 0 (red), z = 0 → exactly 0.5.

The decision boundary is where p = 0.5, i.e. where z = 0. Since z = w₁x₁ + w₂x₂ + b = 0 is the equation of a straight line, this model can only ever split the plane with a straight line. Hold on to that.

For classification the loss is cross-entropy, −ln(probability given to the true class), the same loss your CNN uses. The trainer above minimises it.

§5 · When one line isn't enough

Some patterns aren't straight

One neuron draws one straight boundary. What about a circle (blue inside, red outside), or XOR (blue where x and y have the same sign)? No single line can split those.

Feature: an input number given to the model. Feature engineering: a person invents new features (like x² + y², the squared distance from the centre) so a simple model can solve the problem. In the new feature, the circle becomes "small value vs big value", which one straight cut can split. This is how much of classical ML works: humans design the features.
§6 · Layers and non-linearity

Let the network invent its own features

Instead of hand-designing features, feed the inputs to a layer of several neurons, then feed their outputs to one more neuron. With x as the input vector:

ŷ = W₂ · σ(W₁x + b₁) + b₂
Layer: a row of neurons that all see the same inputs. With matrices, the whole layer is one line: W₁x + b₁, where row i of W₁ holds neuron i's weights. Hidden layer: a layer between input and output. Its outputs are the network's own invented features.
A 2 → 4 → 1 network with fixed example weights hand-picked weights
activation σ
The 4 hidden neurons: features the network made

Why the activation matters: without it, W₂(W₁x + b₁) + b₂ = (W₂W₁)x + (W₂b₁ + b₂), which is just one matrix times x plus one bias: a single straight-line model, however many layers you stack. The bend (ReLU, tanh…) is what lets the boundary bend.
The real line between classical ML and deep learning

In §5 you designed x² + y². Here the hidden layer builds features itself, and in a trained network they're learned from data by the same gradient descent as §2. Deep learning = many layers that learn their own features. Your CNN's filters are exactly this: features nobody hand-designed.

§7 · The training loop

Forward, loss, backprop, step

With many layers, how do we get each weight's gradient? Backpropagation, or "backprop", is the chain rule from calculus run backwards through the network. Here it is on the smallest possible chain: one input, two weights, one training example.

x = 1.5 → h = w₁x → ŷ = w₂h → L = (ŷ − y)², target y = 2
Press ① to start.
BackpropComputes ∂L/∂w for every weight with the chain rule. Changes nothing.
OptimizerUses those gradients: w ← w − lr·∂L/∂w. Computes no gradients.

§9 · Towards images

Images need a smarter layer

An image is just numbers: a 28 × 28 grayscale picture is 784 brightness values. You could flatten it and feed it to the networks above.

One FashionMNIST-style image hand-drawn
28 × 28 = 784 inputs
neurons

Problem 1: too many weights. A fully connected layer gives every pixel its own weight into every neuron, so the count explodes, and more weights need more data to learn.

Problem 2: it ignores neighbours. A fully connected layer has no idea which pixels sit next to each other. Shuffle the pixels in a fixed order and, to that layer, nothing has changed. To you, the image is gone.

Convolutional neural network (CNN): a network whose early layers use small filters (e.g. 3 × 3 = 9 weights) that slide across the image. Each filter looks only at a pixel's neighbours (fixes problem 2), and the same 9 weights are reused at every position, called weight sharing (fixes problem 1). Your conv1 layer has 16 such filters: 16 × 9 = 144 weights + 16 biases.
